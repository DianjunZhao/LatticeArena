## Numerical implementation completed in this audit

`TwoStateFit` now solves the linear amplitudes after Cholesky whitening with `numpy.linalg.lstsq` (SVD), rather than solving the normal equations. The returned diagnostics include the SVD rank, design-matrix condition, the historically reported normal-matrix condition `cond(XᵀWX) = cond(W¹ᐟ²X)²`, and a fit status. Equal masses are explicitly classified as `nested_m1_boundary`; rank deficiency is not reported as a resolved two-state fit. No condition-number pass threshold was added.

The focused CPU regression covers equivalence with the previous normal-equation answer at a well-conditioned point, the equal-mass nested boundary, a near-degenerate gap, invalid means, endpoint retention, and optimizer exceptions. `tests/test_pion_twostate_stable.py` now passes **11 tests**; the full Pion selection `tests/test_pion*.py -rs` passes **96 tests**.

The new `TwoStateFit.fit_full_multistart` routine runs an explicitly supplied (or deterministic default) family of constrained SLSQP starts in `(mass0, gap)`. It records every endpoint, optimizer status/message/exception, call and iteration counts, feasibility, mass-boundary class, amplitude rank, condition and amplitudes. It returns only `diagnostic_only`; a lowest finite endpoint from a nonconverged solver is labeled nonconverged, and no global-minimum or physics gate is implied.

`iter_bootstrap_multistart` accepts a complete integer block-index matrix and explicit fixed starts. Before fitting, it emits a strict-JSON manifest with planned draw count and hashes for the resampling matrix, starts, fixed precision, fit configuration and executor source; it then yields every draw with its resampled block indices and all per-start results. [`bootstrap_checkpoint.py`](../../../tasks/pion_projection/bootstrap_checkpoint.py) adds an explicit no-clobber JSONL journal: each complete draw is hash-chained and fsynced, and resume verifies the manifest and all committed rows before rerunning an incomplete draw. The runner also binds the fit sample matrix hash/shape, per-channel normalization scales and ordered configuration IDs in each block. Its diagnostic data flow and limits are documented in [`bootstrap_checkpoint_report.md`](../../../tasks/pion_projection/bootstrap_checkpoint_report.md). The checkpoint writer has **5 focused CPU tests**; combined with the 11 stable-fit tests, **16 tests pass**. These tests establish persistence/recovery mechanics only, not reference-gate validity or calibration.

The implementation was replayed on the hash-audited public D0–99 inputs using the exact archived 29 starts per window. All 87 endpoints matched the previous D-only multi-start output exactly in mass and cost; each window retained 24/29 SLSQP success flags, and failed endpoints remained at the nested boundary. This is same-input implementation parity, not a new sample or independent validation. The table, row-level CSV and parity graph are in [`two_state_executor_replay_20261120_v1`](../two_state_executor_replay_20261120_v1/README.md).

Latest full CPU suite: **270 passed, 1 skipped, 1 warning**; the skip is the unavailable CuPy stout parity test and the warning is the known Wilson rejection path. This does **not** replace the legacy `fit_full()` / `bootstrap()` search path, which still uses coordinate search and excludes `gap=0`. The new multi-start method is an explicit diagnostic API; it has not yet been wired into a frozen confirmatory bootstrap, gate, or production reference. A stable numerical search is necessary but not sufficient for a confirmatory M2 executor.
